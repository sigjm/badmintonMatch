# 정모 관리와 운영 기록 — 설계

작성일: 2026-10-22

## 목적

운영자가 현재 선택한 모임의 정모를 직접 추가하고, 잘못되었거나 더 이상 운영하지 않는 정모를 보관 처리할 수 있게 한다. 참석자·경기·설정 변경을 포함한 운영자 작업 이력을 한 화면에서 확인할 수 있게 한다.

## 사용자 확인 사항

- 정모를 운영자 화면에서 추가하고 삭제할 수 있어야 한다.
- 삭제는 데이터를 영구 제거하지 않고 보관 처리한다.
- 로그 범위는 회원 정보 변경에 한정하지 않고 운영자 전체 작업 기록으로 한다.
- 정모 목록과 정모 상세 화면에 삭제 버튼을 둔다.

## 설계 요약

정모는 `archived_at` 값이 있는지로 활성·보관 상태를 구분한다. 보관할 때 관련 참석자, 경기, 예약 데이터는 유지한다. 운영 화면에는 활성 정모와 보관 정모를 구분해 보여 주고, 운영자는 보관된 정모를 복구할 수 있다.

운영 변경 이력은 기존 회원별 `changes` 기록과 별도의 `audit_logs` 테이블에 저장한다. 로그 화면에서는 두 기록을 시간순으로 합쳐 보여 주며, 기존 이력은 마이그레이션하거나 삭제하지 않는다.

## 정모 추가와 보관

- 정모 관리 첫 화면에 날짜와 정모 이름을 입력하는 수동 추가 폼을 둔다. 새 정모는 현재 선택한 모임에 속한다.
- 날짜와 이름은 필수다. 같은 모임 안에 같은 날짜·이름의 활성 정모가 이미 있으면 중복 레코드를 만들지 않고 기존 정모로 이동한다.
- 보관 정모는 자동으로 활성화하지 않는다. 동일한 소모임 이벤트 ID를 다시 불러오려는 경우 중복 생성을 피하고, 운영자에게 보관 정모를 먼저 복구하라고 안내한다.
- 활성 정모 목록의 각 행과 정모 상세 화면에 `삭제` 버튼을 둔다. 버튼은 확인 후 POST 요청으로 보관 처리한다.
- 정모 목록에서 활성·보관 항목을 구분한다. 보관 항목에는 `복구` 동작을 제공한다. 보관된 정모의 상세 화면은 조회 전용이며 정모 운영 변경을 막는다.
- 보관된 정모는 공개 대진판과 활성 정모 목록에 나타나지 않고, 자동 매칭·예약 채우기 대상에서도 제외한다. 진행 중인 정모를 보관하면 공개 대진판에서 즉시 숨긴다.
- 보관·복구는 참석자·경기·예약 및 정모의 기존 운영 상태를 보존한다. 복구하면 보관 전 상태로 되돌아간다.
- 정모 삭제 권한과 요청 보호는 기존 운영자 로그인 및 같은 출처 POST 보호를 따른다. 영구 삭제 기능은 제공하지 않는다.

## 수동 예약과 선수 이름 표시

- 수동 대진에서 고른 네 명은 코트에 즉시 배정하지 않고 예약 목록에 추가한다.
- 새 수동 예약은 현재 예약의 순서를 유지하면서 맨 뒤에 추가한다. 자동 예약 수가 코트 수에 도달했더라도 운영자가 지정한 수동 예약은 유지한다. 자동 예약은 기존처럼 코트 수에 맞춰 채운다.
- 예약은 번호 순서대로 다음 빈 코트에 배정한다. 수동 예약에 포함된 선수는 예약이 소진되기 전까지 대기열의 다른 자동 예약 후보로 다시 잡히지 않는다.
- 수동 예약은 경기로 배정되거나 운영자가 삭제할 때까지 유지한다. 수동 예약에서는 `다시 뽑기`를 제공하지 않으며, 내용을 바꾸려면 삭제 후 새 수동 예약을 만든다.
- 운영자는 현재 참석 중인 선수를 성별이나 급수 입력 여부와 관계없이 수동 예약에 넣을 수 있다. 수동 예약을 코트에 넣을 때 참석 상태, 경기 중 여부, 중복만 확인하고 자동 매칭의 급수·성비 조건은 적용하지 않는다.
- 수동 예약 생성과 예약에서 경기로 배정되는 전환을 운영 로그에 남긴다. 대기열에서 자동 경기로 배정되는 작업도 로그에서 추적할 수 있어야 한다.
- 선수 이름 표시는 성별에 따라 적용한다. 대기열·제외·코트·예약의 사람 카드 배경은 남성 파랑, 여성 자주색, 성별 미입력 회색으로 하고 이름은 흰색으로 표시한다. 회원 목록의 이름 텍스트는 남성 파랑, 여성 기존 자주색, 성별 미입력 기본색을 사용한다. 수동 대진 초안은 남성 이름 파랑, 여성 기존 자주색을 유지한다. 카드 배치와 나머지 화면 표현은 유지한다.

## 운영 로그

### 저장 형식과 처리

새 `audit_logs` 테이블은 시간, 행위자, 작업 종류, 대상 종류와 ID, 관련 정모 ID, 화면에 표시할 요약, 필요한 변경 세부사항을 저장한다. 로그는 해당 변경과 같은 DB 트랜잭션 안에서 기록한다. 변경이 실패하면 성공 이력도 남기지 않는다.

현재 운영자 인증은 공용 계정이므로 행위자는 `운영자`로 기록한다. 로그인, 로그아웃, 화면 조회, 검색, 자동 새로고침 같은 읽기 동작은 기록하지 않는다. 기존 `changes`의 회원 정보 변경 기록도 그대로 두고, 로그 화면에서 새 운영 로그와 함께 시간순으로 보여 준다.

로그 화면은 날짜, 작업 종류, 정모 기준 필터와 페이지 이동을 제공한다. 시각은 Asia/Seoul 기준으로 표시한다. 로그를 수정하거나 삭제하는 UI와 자동 보존기간은 제공하지 않는다.

### 기록할 작업

- 정모 수동 추가, 소모임 불러오기·붙여넣기 결과, 정모 보관과 복구
- 참석자 추가와 제거, 상태·급수·성별·메모 변경, 게스트 추가
- 정모 시작, 코트 수 변경, 자동 경기 배정, 수동 예약 생성, 경기 종료·다시 뽑기, 예약 다시 뽑기
- 여자 보정값과 매칭 후보 범위 같은 운영 설정 변경
- 회원 정보 변경, 회원 이름 변경, PIN 초기화, 모임 추가와 이름 변경

각 항목은 작업 대상과 변경 전·후 값이 실제로 필요한 범위에서만 저장한다. PIN 원문·해시, 운영자 비밀번호, 세션값 및 기타 인증 비밀은 로그에 기록하지 않는다. PIN 초기화는 실행 사실만 기록한다.

## 데이터와 호환성

- `meetups`에 nullable `archived_at`을 추가한다. 기존 정모는 모두 활성 상태로 남는다.
- `audit_logs`는 기존 DB 연결 초기화 시 자동으로 생성한다.
- `reservations`에 예약 출처(`auto` 또는 `manual`)를 추가하고, 기존 행은 `auto`로 취급한다. 자동 예약 상한은 자동 생성 예약 수에만 적용하며, 수동 예약 행은 그 상한 때문에 삭제하지 않는다.
- 기존 `changes`와 정모 관련 데이터는 변경하거나 지우지 않는다.
- 공개 대진판의 현재 정모 선택, 운영 화면의 최근 정모, 정모별 자동 매칭·예약 채우기 조회에서 보관 정모를 제외한다.
- 정모의 `eid`는 기존 유일성을 유지한다. 보관된 이벤트를 불러오는 작업은 같은 이벤트를 중복 생성하지 않으며, 운영자가 복구하기 전까지 보관 상태를 유지한다.

## 완료 기준

1. 운영자가 현재 선택한 모임에 날짜와 이름을 입력해 정모를 추가할 수 있고, 같은 활성 정모를 중복 추가하지 않는다.
2. 활성 정모 목록과 상세 화면에서 정모를 보관할 수 있으며, 확인 후 목록이 최신 상태로 갱신된다.
3. 보관 정모는 공개 대진판과 자동 운영에서 제외되고, 운영자가 목록에서 복구할 수 있다. 복구 전후 참석자·경기·예약 데이터가 보존된다.
4. 운영 로그 화면에서 기존 회원 변경과 새 운영 변경 기록을 시간순으로 조회하고, 날짜·종류·정모 필터와 페이지 이동을 사용할 수 있다.
5. 변경 작업과 로그 기록은 원자적으로 처리되며, PIN·비밀번호·인증 비밀이 로그에 포함되지 않는다.
6. 수동 대진에서 고른 네 명은 기존 예약 순서를 보존한 채 수동 예약으로 추가되며, 빈 코트에 즉시 배정되지 않는다.
7. 대기열·제외·코트·예약 사람 카드는 남성 파랑, 여성 자주색, 성별 미입력 회색 배경과 흰색 이름으로 표시되고, 회원 목록과 수동 대진 초안의 성별 이름색도 구분된다.
8. 성별·급수가 비어 있는 현재 참석자도 운영자가 수동 예약에 넣을 수 있고, 자동 매칭 조건은 그대로 유지된다.

## 범위 밖

- 로그 수정·삭제, 로그 내보내기, 보존기간 설정
- 개별 운영자 계정과 작업자별 식별
- 보관 정모의 영구 삭제
- 운영 서버 배포 또는 운영 DB의 수동 변경

## 검토할 운영 시나리오

- 날짜·이름을 통한 정모 추가, 같은 정모의 중복 요청, 보관 상태에서 재불러오기
- 진행 중인 정모 보관과 복구, 보관 정모 직접 접근, 공개 대진판에서의 노출 여부
- 참석자·경기·설정 변경의 로그 표시와 시간순 정렬
- PIN 초기화 이력에 민감한 값이 기록되지 않는지 확인
- 기존 `changes` 이력과 기존 정모 데이터가 그대로 보이는지 확인
- 자동 예약이 이미 코트 수만큼 있는 상태에서 수동 예약을 추가하고, 모든 예약이 순서대로 코트에 배정되는지 확인
- 대기열·제외·코트·예약 사람 카드의 남성·여성·성별 미입력 배경과 회원·수동 대진 이름색 확인
