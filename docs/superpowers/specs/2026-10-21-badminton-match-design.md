# 배드민턴 정모 자동 매칭 — 설계

작성일: 2026-10-21

## 왜 만드나

지금은 정모마다 운영진이 소모임 앱에서 참석자 명단을 보고 한 명씩 손으로 등록한 뒤, 급수를 보며 밸런스가 맞게 대진을 직접 짠다. 이 시스템은 그 두 가지를 자동으로 한다.

1. 지정한 날짜의 정모 참석자를 소모임에서 자동으로 불러와 등록한다.
2. 급수와 성별을 기준으로 혼복 밸런스를 맞춰, 코트가 빌 때마다 다음 경기를 자동으로 짠다.

대상 모임: 소모임 **"금요일 야간민턴"** (서울 노원구, 모임 ID `9b34753d-4105-4c55-9310-bb923ba2a8e61`). 첫 테스트 데이터는 2026-10-23(금) 22:00 정모 "금야민+게1"(더콕배드민턴센터, 참석 20/21)이다.

## 목표

- 운영진이 날짜를 고르고 "불러오기"를 누르면 그날 정모 참석자가 등록된다.
- 회원별 성별과 급수가 DB에 남아 있어서, 다음 정모부터는 다시 입력할 필요가 없다.
- 코트가 끝날 때마다 다음 경기가 자동으로 나오고, 경기 수가 고르고, 팀 실력이 비슷하다.
- 운영진과 회원 모두 폰 브라우저에서 앱 설치 없이 쓴다.

## 하지 않는 것

- 경기 점수와 승패 기록
- 같은 파트너나 상대가 반복되는지 고려 (사용자가 "크게 상관없다"고 함)
- 정해진 시간에 명단을 자동으로 가져오는 기능 (버튼으로만 가져옴)
- 운영진 개인 계정, 카카오 로그인

## 하면 안 되는 것

- 소모임 계정 정보(아이디, 비밀번호, 세션)를 시스템에 저장하는 것. 명단은 로그인 없이 공개 페이지에서만 가져온다.
- 급수가 없는 사람을 임의의 급수로 경기에 넣는 것. 밸런스가 깨진다.

## 소모임 연동 (확인된 사실)

소모임은 공개 API가 없다. 대신 2024년 12월에 출시된 소모임 웹의 모임 페이지 `https://www.somoim.co.kr/<모임ID>`를 **로그인 없이** 일반 HTTP GET으로 받으면, HTML 안의 Next.js 스트리밍 데이터(`self.__next_f.push(...)` 인라인 스크립트, 따옴표가 `\"`로 이스케이프된 상태)에 다음이 들어 있다.

- **정모 목록** `"events":[...]`: 정모마다 `en`(이름), `e_d`(날짜 `YYYYMMDD` 숫자), `e_t`(시각 `HHMM` 숫자), `el`(장소), `emm`(정원), `enum`(정모 슬롯 번호 1~4)
- **회원 목록**: 회원마다 `{"id":…,"gid":…,"mid":<회원ID>,"mn":<닉네임>, …,"ban":"Y|N","ijo":"Y|N","ijo2":…,"ijo3":…,"ijo4":…}`
  - `ijo`는 슬롯 1번 정모, `ijo2`~`ijo4`는 슬롯 2~4번 정모에 참석하는지를 나타낸다.
  - 운영진이 두 번 나오는 등 같은 회원이 중복될 수 있으므로 `mid`로 중복을 제거한다.

검증 결과:

- Team ONAM 모임: 참석 표시 9명이 화면의 9/12와 일치했다.
- 금요일 야간민턴 모임: 참석 표시 20명이 화면의 20/21과 일치했다.
- 둘 다 `ijo`(슬롯 1)만 확인했다. `ijo2`~`ijo4`가 슬롯 2~4와 대응한다는 것은 필드 이름에서 추정한 것이고, 그 슬롯에 정모가 있을 때 검증해야 한다.
- 금요일 야간민턴의 회원 레코드는 고유 `mid` 기준 170개인데, 화면의 회원 수는 164명이다. 차이는 탈퇴 또는 차단 회원일 가능성이 있다. 참석 판정에는 영향이 없다.

불러오기 동작: 선택한 날짜와 `e_d`가 같은 정모를 찾고, 그 정모의 `enum`에 맞는 `ijo*` 필드가 `"Y"`인 회원을 참석자로 등록한다. 같은 날짜에 정모가 둘 이상이면 운영진이 고른다.

깨질 때의 대비: 소모임이 페이지 구조를 바꿔서 파싱에 실패하면, 원인을 화면에 알리고 **붙여넣기 입력**(소모임 앱에서 복사한 참석자 닉네임을 줄 단위로 붙여넣기)으로 대신한다. 붙여넣은 닉네임은 회원 DB의 닉네임과 맞춘다.

이 방식은 공개 페이지를 읽는 비공식 방식이다. 계정이 제재받을 위험은 없지만 소모임이 화면을 바꾸면 깨질 수 있고, 사용자가 이 점을 알고 선택했다.

## 회원과 급수

- 회원은 소모임 `mid`를 키로 저장한다(닉네임이 바뀌어도 같은 사람). 항목: 닉네임, 성별(남/여), 급수, PIN 해시, 게스트 여부.
- 급수 단계와 점수: S=6, A=5, B=4, C=3, D=2, 초심=1.
- **여자 보정**: 여자의 매칭 점수는 급수 점수에서 보정값을 뺀 값이다. 보정값은 기본 1이고 운영진이 설정에서 바꿀 수 있다.
- **급수가 없는 사람**은 매칭에서 제외한다. 불참이나 지각처럼 따로 보이게 두고, 급수가 입력되는 순간 대기열 맨 뒤에 들어간다. 성별이 없는 경우도 같게 처리한다.
- **회원의 직접 수정**: 회원 링크에서 자기 닉네임을 고르고 4자리 PIN으로 성별과 급수를 수정한다. PIN이 없으면 처음 들어왔을 때 정한다.
- **운영진 수정**: 운영진은 누구의 정보든 PIN 없이 수정한다. PIN 초기화도 할 수 있다.
- 급수 변경 기록(누가, 언제, 무엇을 무엇으로)을 남기고 운영진이 볼 수 있게 한다.
- **게스트**는 소모임 명단에 나오지 않으므로 운영진이 당일 이름, 성별, 급수를 넣어 추가한다. 게스트로 표시해 저장해 두고, 다음에 다시 고를 수 있게 한다.

## 매칭

정모 당일 운영진이 코트 수를 입력하고 "시작"을 누르면 모든 코트에 첫 경기를 채운다. 이후 코트 하나가 끝나서 "경기 끝"을 누를 때마다 그 코트의 다음 경기를 한 경기씩 만든다.

**대기열**: 상태가 참석이고, 성별과 급수가 있고, 지금 경기 중이 아닌 사람. 다음 순서로 정렬한다.

1. 오늘 경기 수가 적은 사람
2. 오래 기다린 사람 (마지막 경기가 끝난 시각, 또는 대기열에 들어온 시각이 이른 순)

**4명 고르기** (2026-10-21 사용자 요청으로 변경: "점수 차이는 신경 쓰지 말고, 각자 급수만 비슷하게")
- 대기열 맨 앞 사람은 반드시 넣는다.
- 경기 수가 가장 적은 사람이 앞쪽 몇 명(기본 6명) 안에 4명 이상이면, 그 사람들 안에서만 고른다.
- 나머지 3명은 다음 기준으로 고른다.
  - 4명의 급수 폭(최고 - 최저, 여자 보정 적용)에 직전 경기에서 같이 친 쌍의 수 × 2를 더한 값이 가장 작은 조합
  - 같으면 혼복 → 남복·여복 → 대기 순서가 앞인 조합
- 남3여1이나 남1여3 경기는 급수 우선의 결과로 나올 수 있다. 사용자가 따로 정하지 않았다.

**팀 나누기**: 4명을 두 팀으로 나누는 3가지 경우 중에서, 두 팀 점수 합의 차이가 가장 작은 것을 고른다. 남2·여2라면 혼복이 되는 2가지 경우 중에서만 고른다.

**상태 변경**: 운영진은 참석자를 참석, 지각(아직 안 옴), 자리 비움, 귀가로 바꿀 수 있다. 참석이 아닌 사람은 대기열에서 빠진다.

**다시 불러오기**는 명단을 갱신하는 기능이다.
- 새로 참석한 사람이 추가된다.
- 소모임에서 참석을 취소한 사람은 **취소** 상태가 된다.
- 취소했던 사람이 소모임에서 다시 참석하면 참석으로 돌아온다.
- 게스트와 붙여넣기로 추가한 사람은 다시 불러와도 바뀌지 않는다.

**다시 뽑기**: 경기가 막 만들어졌는데 그중 누가 바로 칠 수 없으면, 운영진이 그 사람을 자리 비움으로 바꾸고 해당 코트의 "다시 뽑기"를 누른다. 그러면 나머지 사람은 대기 순서를 그대로 유지한 채 대기열로 돌아가고, 그 코트의 경기를 새로 만든다.

대기 인원이 4명보다 적으면 그 코트는 비워 두고, 4명이 되는 순간 경기를 채운다.

경기 수와 대기 순서는 정모마다 0부터 시작한다.

## 화면

모두 폰 세로 화면 기준이다.

- **운영진** (공용 비밀번호로 로그인)
  - 정모: 날짜 선택, 불러오기, 붙여넣기(대비용)
  - 참석자: 상태 변경, 급수 미입력 표시와 바로 입력, 게스트 추가
  - 코트 보드: 코트 수, 시작, 코트별 현재 경기, 경기 끝, 대기열
  - 설정: 여자 보정값, 혼복 후보 범위
  - 회원 관리: 급수, 성별 수정, PIN 초기화, 변경 기록
- **회원** (로그인 없음)
  - 내 정보: 닉네임 고르기, PIN 입력, 성별과 급수 수정
  - 대진 보기: 코트별 현재 경기와 대기 순서 (읽기 전용, 자동 새로고침)

## 기술과 배포

- Python 서버 하나가 HTML을 렌더링한다. 데이터는 SQLite 파일 하나에 저장한다.
- 대상 서버: 사용자의 Ubuntu 24.04 서버(`sigjm@192.168.75.208`, 내부망). Docker가 있고, 다른 서비스도 컨테이너로 돌아간다.
- 외부 공개: 이 서버는 Cloudflare 터널(`cloudflared` 컨테이너, 토큰 방식, Docker 네트워크 `server-edge_default`)로 `*.jmllem.com` 서브도메인을 공개한다. 이 앱은 **`badminton.jmllem.com`** 으로 연다. 터널이 Cloudflare 대시보드에서 관리되므로, 공개 호스트 이름 추가는 사용자가 대시보드에서 직접 한다. 배포하는 쪽은 컨테이너 이름과 포트를 알려 준다.
- 컨테이너를 `server-edge_default` 네트워크에 붙이고, SQLite 파일은 호스트 볼륨에 둔다.
- 운영진 비밀번호는 환경 변수로 넣는다. PIN은 해시로 저장한다.
- 날짜와 시간은 Asia/Seoul 기준이다.

## 만드는 사람이 정할 것

- 웹 프레임워크, 템플릿, 프론트엔드 방식. 코트 보드 자동 새로고침은 폴링으로 충분하다.
- 테이블 구조와 이름
- 파싱 구현 방식 (정규식 또는 JSON 조각 디코딩)
- 혼복 후보를 찾는 범위인 "대기열 앞쪽 몇 명"의 기본값 조정. 설정으로 바꿀 수 있게 둔다.

## 사용자가 아닌 설계자(Claude)가 정한 것

- 경기 점수를 기록하지 않는다.
- 경기 수는 정모마다 0부터 다시 센다.
- 혼복 우선은 대기열 앞쪽 6명 안에서만 찾아, 경기 수 공평성을 크게 해치지 않게 한다.
- 성별이 없는 사람은 급수가 없는 사람과 똑같이 매칭에서 제외한다.
- 취소했다가 소모임에서 다시 참석한 사람은 다시 불러올 때 참석으로 되돌린다. 취소 상태는 다시 불러오기만 만들기 때문에, 운영진이 직접 바꾼 상태를 덮어쓰지 않는다.
- 같은 날짜에 정모가 여럿이면 운영진이 고른다.
- 경기가 만들어진 뒤 사람을 바꿀 때는 "다시 뽑기"로 한다. 직접 한 명씩 바꿔 넣는 기능은 두지 않는다.
- 운영진 비밀번호는 환경 변수로만 바꾼다. 화면에서는 바꿀 수 없다.
- PIN을 아직 정하지 않은 회원의 닉네임은 다른 사람이 먼저 골라 PIN을 정할 수 있다. 이런 경우 운영진의 PIN 초기화로 해결한다.

## 추가 (2026-10-21): 모임 선택

사용자 요청으로 여러 소모임 모임을 골라 쓸 수 있게 했다.

- **모임 추가**: 운영진이 소모임 모임 링크를 붙여넣어 추가한다. 이름을 비워 두면 소모임 페이지의 `<title>`에서 가져온다.
- **모임 고르기**:
  - 운영진은 정모 화면 위쪽의 모임 탭으로 고른다. 고른 모임은 세션에 저장된다.
  - 대진 화면은 `?g=<모임>` 탭으로 고른다. 고르지 않으면 가장 최근에 진행한 정모의 모임을 보여 준다.
- **모임 기준으로 동작하는 것**: 불러오기, 최근 정모, 붙여넣기로 만든 정모는 선택한 모임 기준이다. 다시 불러오기는 그 정모의 모임 기준이다.
- **회원**: 회원(급수, 성별, PIN)은 모임과 관계없이 한 사람으로 공유한다. 소모임 회원 ID가 같으면 같은 사람이다.
- **기본 모임**: 처음 실행할 때 기본 모임 "금요일 야간민턴"을 만들고, 기존 정모를 그 모임에 연결한다.

## 추가 (2026-10-21): 모임 이름으로 찾기

모임 관리 화면에서 이름을 검색하면 소모임 웹 검색(`/groups/search?keyword=`) 결과를 보여 준다. 운영진이 결과 중 하나를 골라 추가한다. 링크 붙여넣기도 계속 쓸 수 있다. 소모임 계정 로그인이 없어서 "내가 가입한 모임" 목록은 자동으로 가져올 수 없다.
